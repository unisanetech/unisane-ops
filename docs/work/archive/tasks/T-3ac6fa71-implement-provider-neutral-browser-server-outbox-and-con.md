## Changelog

## Goal

Implement provider-neutral browser, server, outbox, and consent observation adapters

## Acceptance

- Runtime-neutral observation v2 schemas live in @unisane/web-runtime/contracts; Growth consumes only that contract subpath and Web Runtime has no Growth, Ops Engine, provider-management, Framework, or adopter-product dependency.
- Framework-neutral browser, server, outbox, and consent adapters produce the same strict redacted observation contract, hash private identity inputs before output, and accept only field-state evidence rather than raw customer or transport values.
- Observation ingestion validates project, environment, schema version, bounded size, and redaction; an idempotent sink is replay-safe without hiding distinct browser deliveries or server attempts.
- Portable commerce and lead fixtures prove two unrelated adopters can generate and ingest compatible observations without ECOM-specific code or schema coupling.
- Focused adapter, contract, compatibility, privacy, idempotency, and reconciliation tests pass with Web Runtime and Growth tests, type checks, lint, builds, formatting, symbols, and repository integrity.

## Non-Goals

- Do not integrate ECOM source, implement canonical outcomes, connect Meta, call providers, publish GTM, mutate provider configuration, or add console/MCP/API behavior.

## Constraints

- Keep canonical outcomes, tracking delivery evidence, and provider attribution as separate models.
- Original identity and customer values may exist only ephemerally inside the adopter runtime; emitted evidence contains SHA-256 identity digests and bounded states only.
